# How this differs from a fresh bundle, and who maintains which part

Two things a reader needs and cannot get by looking: what we changed relative to a fresh
`lokf new`, and which parts of this repository are ours to fix.

## Changed from the scaffold

`lokf new` produces a working knowledge base. This is that, minus some things and plus others.
Anyone diffing against a fresh scaffold will see these.

**Removed**

- `.claude/skills/` — six Claude agent skills the scaffold writes. They reference
  `examples/acme-knowledge` thirteen times across three files, and `lokf new` does not create
  that directory, so an agent following them here would run commands against a missing path.
  Reported upstream as https://github.com/nicholsn/lokf/issues/34. Restore them with
  `lokf skills install` if you want them.
- The scaffold's starter concepts, `weekly-active-users` and `active-user`, replaced by the six
  concepts here.

**Changed**

- **Base IRI.** Concepts were first named under `https://w3id.org/turbomam/nmdc-lokf-demo/`, a
  prefix nobody had registered in `perma-id/w3id.org`, so all six subjects returned 404. They are
  now named at the GitHub Pages origin, where each subject resolves to its own page. See
  [lessons.md](lessons.md).
- **`knowledge/index.md`** replaced the scaffold defaults: `base_iri`, `title`, `description`, and
  a `license` line that had said CC-BY while `LICENSE` said AGPL-3.0.
- **`src/lib/lokf.ts`** and **`astro.config.mjs`**, whose `BASE_IRI` and `site` had to move with
  the base IRI. The scaffold sets all four places at once if you pass `--base-iri` to `lokf new`;
  doing it by hand is where this went wrong.
- **`src/pages/index.astro`** renders a dated provenance notice. The scaffold's homepage is
  hard-coded and excludes `knowledge/index.md` from the Astro collection, so bundle-level
  metadata reaches no reader.
- **`src/styles/global.css`** gained a `.notice` rule, with the notice's link underlined at all
  times. Site-wide, links are `text-decoration: none` until hover, which leaves an inline prose
  link distinguished by colour alone. Reported upstream as
  https://github.com/nicholsn/lokf/issues/35.
- **`.github/workflows/pages.yml`** uses `npm ci` rather than `npm install`, and
  `package-lock.json` is committed. The scaffold's own comment asks for this.

**Added**

- `.github/workflows/check.yml`, which validates the bundle and fails if `knowledge.ttl` has
  drifted from the concepts.
- `docs/`, `queries/`, and a committed `knowledge.ttl`.

## Who maintains what

This repository mixes four sources. Knowing which is which tells you where to file.

| Part | Who maintains it | Where issues go |
|---|---|---|
| `knowledge/`, `queries/`, `docs/`, this README | Us | Here |
| `src/`, `astro.config.mjs`, `justfile`, `package.json`, `.github/workflows/pages.yml` | Generated by `lokf new`, edited here. Upstream template maintained by Nolan Nichols | Template problems upstream; our edits here |
| `.github/workflows/check.yml`, `scripts/lint-site-prose.py` | Us. Written here, not scaffolded | Here |
| The LOKF format, `lokf.yaml` and everything generated from it | Nolan Nichols | https://github.com/nicholsn/lokf |
| The findings the concepts describe | The BERIL Research Observatory `nmdc_context_audit` project | https://github.com/kbaseincubator/BERIL-research-observatory |

**Maintained by Mark Miller (LBNL).** Issues about the bundle content, the site, or these
documents belong here. Issues about the format or the toolkit belong upstream.

**This is an exercise, not a product.** It is not an NMDC deliverable and nothing here is
authoritative about NMDC data. For anything operational, use the sources.
